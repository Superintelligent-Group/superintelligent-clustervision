## Verdict

cv is drifting. The curve is a straight line, about 20K lines a month, with no plateau:

| month end | Rust lines (incl. tests) | top-level commands |
|---|---|---|
| June | 54K | 32 |
| July | 72K | 33 |
| September | 92K | 37 |
| October 10 | 110K | 43 (+27 `task`, +13 `board`) |

Of the 110K, about 67K is code and 43K is tests. The essential power (read every harness's real
store losslessly into one IR; find and search across all of it; read behind compactions; reshape a
session into something a harness resumes; see a swarm while it runs) is intact and, in places,
excellent. Around it has grown a second product (a verified-landing task substrate with its own
trust layer, a board that duplicates the task log, three binaries, two HTTP servers, four UIs) and
a layer of copies (two wire codecs typed fifteen times, seven reshape verbs over two primitives,
ten copies of the test harness). The single change that most bends the curve: **every door is a
mapping onto one function per noun, never a second implementation.** Most of the sprawl is a
second implementation of something that already existed one crate over.

Roughly a quarter of the code, a third of the tests, and a third of the prose come out without
losing power. The estimates below overlap across areas; treat them as magnitudes.

## The attractor

**Three crates, one binary, one API, one UI, ~30 verbs, two reshape primitives.**

- `cv-core`: IR, adapters, emit, the read API that every door maps onto, tasks, lanes, watch.
  `cv-search` stays the one satellite only because tantivy does not belong inside the dependency
  fence. `cv-web` is the wasm cdylib.
- `cv`: `cv <verb>`, `cv mcp`, `cv serve`, `cv watch`. `cvd` and `cv-mcp` are subcommands, not
  binaries. The MCP roster is generated from the in-process clap tree, so it cannot skew from the
  CLI (today it shells out to whatever `cv` is on PATH and found a stale one).
- **An adapter is `roots + discover + record-to-Message stream`, 150 to 400 lines**, importing
  its wire codec (`harness/wire/{anthropic,openai}`) and its store helper
  (`harness/store/{jsonl,sqlite}`). Emitters live beside their readers and are the codec run
  backwards plus a store writer. Grok, at 500 lines, is the model, not Claude.
- **Two reshape primitives, each spelled once.** Record-level and lossless for Claude:
  `derive(src, Select, Rewrite)`, where prune, rewind and adopt are 30 to 80-line selectors.
  IR-level for any harness in: `select messages, then emit(Claude)`, where the emitter itself
  guarantees linear parents, no orphan `tool_use`, correct sidechain identity and the sidecar, so
  fork, distill, splice and `pack --format session` are 20 to 50-line selectors and `loom`,
  `linearize`, `restamp` and the emit-read-rewrite dance do not exist.
- **A task is an append-only log of about eleven event kinds** folded by a ~450-line pure
  reducer under one CAS. A decision is a task with a `posed`; one event poses, one answers,
  provisional-then-confirm is the one override. Completion is self-reported and labeled so.
  Lanes are a pure function of the session directory, never stored. One wake primitive
  (`Watcher` with a cursor), one notify channel (`task events --since`), no board.
- **One hand-written guide of about twelve chapters**, one generated command reference from
  `cv schema --commands --json`, one contract with a test that fails when its command table
  disagrees with the clap tree, a CHANGELOG whose every heading is a tag, tests where the rule
  lives (reducer rules in the reducer, renders beside the command, one `cv-testkit` World, a
  ~1,200-line CLI smoke file).

A session mid-work asks: is this a `--kind`, a `--sort`, a selector, a route on the one API, or
a reducer event? It is never a new top-level command, binary, server, renderer, scanner or
harness.

## Derp: the findings that are bugs or near-bugs

Fix these regardless of the cut list.

1. **TOFU token gate bypassed by the `web:` alias.** `same_actor` makes `web:ember` equal
   `ember`, the web page builds `web:<who>` from the request body and passes no token, and
   `cv task serve` has a Host check only while offering `--bind 0.0.0.0`. The one HTTP surface
   that writes identity-bearing events has the weaker auth. (`task/identity.rs:115`,
   `task/project.rs:132`, `cmd/task_serve.rs:241-246,465,478`)
2. **`resolve` closes a task with a live reviewed revision.** `Done` checks it; `Posed` and
   `Resolved` do not. The manual says this can never happen. (`task/reduce.rs`, Posed/Resolved arms)
3. **`cv port --to kimi` writes to a store Kimi abandoned in June.** Both kimi adapters say so in
   their headers; there is no `kimi_code::emit`. (`harness/kimi.rs:314-460`)
4. **`message_count` contract broken in five adapters.** grok, gemini, openclaw and goose count
   every role; codex extrapolates from a 2 MiB sample for files over 8 MiB and its own comment
   records being 35x off. `cv ls` prints these beside Claude's correct count. (`ir.rs:796-803`
   vs `codex.rs:2138-2163` et al.)
5. **The MCP server generates its roster from whichever `cv` it finds on PATH.** On this machine
   that was a build without `rewind` while the manual listed it. In-process generation removes
   the class of bug. (`cv-mcp/src/cli_tools.rs:180-233`)
6. **`integrations/` tells agents to call MCP tools deleted in 0.11** (`recall`,
   `project_sessions`, `read_session`, ...) and asserts there is no `cv distill`. 29 files,
   1,103 lines, verified by nothing, last touched June. The shipped `/recall` command cannot work.
7. **Resumability rules live in five places and none is the emitter.** `linearize`, fresh
   threading in loom, three "drop unanswered tool_use" loops, three sidechain-marker strips. The
   invariant "an emitted Claude transcript has no dangling `parentUuid`" is asserted for one
   fixture only. (`distill.rs:1261`, `loom.rs:74-88`, `cmd/distill.rs:109-141,386-400`,
   `rewind.rs:629-637,871-886`, `emit.rs:3908`)
8. **Two HTTP servers on port 7777 with diverging security checks** and the same route
   implemented twice. (`cmd/task.rs:470`, `cvd/src/main.rs:62`, `task_serve.rs:133-147` vs
   `cvd/src/serve.rs:173-204`)
9. **Three hand-written read APIs over the same nouns** (CLI `--json`, cvd `/api/*`, the Tauri
   `local_*` commands, ~470 lines plus ~340 lines of tests asserting they match) and a parity
   test whose only job is to catch their drift.
10. **The contract is stale on its own first table**: Reshape lists seven verbs, the binary has
    ten; `distill` is marked removed; "`task_*` mirrors `cv task`" is false (15 of 27). The doc
    predicted this of itself: "a contract nothing verifies decays into folklore."
11. **The board is a lossy second copy of the task log.** 3,317 of 3,319 board lines in 85 days
    are auto-mirrored task events truncated to 80 chars; zero presence, request, reply or ack.
12. **Dead or orphaned code**: `render::to_plain`, `dataset::to_chatml/to_sharegpt`,
    `lib.rs::subagents_of`, `cline::emit_with_harness`'s unused `harness` parameter beside a
    second 210-line Roo emitter it was written to replace, `decide.rs::is_decide_note`, 14
    board `*_in_dir` helpers, the 0.11 tombstone commands still parsed two releases later,
    a `tools/gen-manifests` referenced by 22 manifests that does not exist.
13. **CI's fmt and clippy steps are `continue-on-error`** and have never gated anything; the
    toolchain floats on `stable`. Current debt is small (3 files of fmt drift, 7 clippy warnings)
    and one commit away from real gates.
14. **0.12.0 and 0.13.0 were never released.** Tags and crates.io stop at v0.11.2; 40 commits
    since; the workspace says 0.13.0. The CHANGELOG is a release log in shape and a session diary
    in content (78 words per bullet).

## Excellence: the invariants every cut must hold

- Lazy spans: a 700 MB record costs 16 bytes until a consumer chooses otherwise (`lazy.rs`).
- `parse == collect(stream)` by construction; the two readers cannot diverge.
- A corrupt line never fails a session, and the skip is never silent (`for_each_json_line`,
  `extra["cv"]["skipped_lines"]`).
- One harness list generates every spelling; one emit registry derives the target list and the
  round-trip test.
- `port --strict` fails only on a loss the target could have avoided (`target_holds`,
  `diff_fidelity`). This is what makes "reshape into something a harness resumes" a checked claim.
- Prune sizes by Claude Code's own usage numbers, mirroring the resume gate exactly.
- Rewind's provenance: stat once, read that prefix, sha256 it, write `.rewind.json`, rename
  atomically. Adopt's byte surgery with an undo test.
- SQLite is opened read-only everywhere; cv never writes a lock into a live store.
- The task store's CAS: replay under lock, validate against the exact state each event lands
  after, one `write_all` per batch; quarantine on read, idempotent apply.
- `Mark::Bytes`: a 1 GB corpus is followable for one `stat` per session.
- The dependency fence; the wire golden; the manifest check in both directions; real-writer
  fixtures ("a fixture cv hand-rolled only proves cv agrees with cv").
- One id grammar, one exit-code contract, one window grammar, one row shape on every door.

## The cybernetic layer

cv is a sensor today; hooks make it an actuator inside the harness. The constraint is that agents
set it up for themselves: one idempotent, reversible command (`cv hooks install claude` /
`cv hooks remove`), hooks whose stdout is a line or two, no daemon, and a short skill beside them
so an agent knows when `rewind`, `show --pre-compaction`, `lanes` and `adopt` apply. This replaces
`integrations/` and lives inside the Reshape and Observe power; it is not new sprawl.

Verified against the Claude Code 2.1.296 docs and binary:

| loop | mechanism | status |
|---|---|---|
| A compaction becomes visible and reversible from inside the model's context | `SessionStart` matcher `compact` injects `additionalContext`; the pre-compaction records stay in the jsonl, and `cv rewind --at` / `show --pre-compaction` read them | one hook, today |
| Relevant history at session start | `SessionStart` `additionalContext`, 10K chars inline before it spills to a file | one hook, today; a capped pack, not a listing |
| Lane lifecycle into the ledger with no model action | `SubagentStart`/`SubagentStop` carry `agent_id`, `agent_type`, `agent_transcript_path`; `TaskCreated`/`TaskCompleted` carry task ids; `async: true` so nothing waits | one hook, today; the spawning call comes from the agent's meta file, which cv already reads |
| Owed decisions at a natural moment | `UserPromptSubmit` `additionalContext` | one hook, today |
| An edit to a file another live session touched recently | `PreToolUse` on `Edit\|Write` answering `ask` or `deny` with a reason, from cv's index of live transcripts | one hook, today, if the lookup reads the index |
| Context pressure before the harness compacts | the live count is only in status-line JSON; cv's transcript-derived estimate (it already mirrors the resume gate) works from a hook with lag | possible, lossy |
| Prune in place, no restart | no hook can supply or replace the compaction summary; `PreCompact` can only block | needs a harness change: a `PreCompact` output that supplies the compacted segment |
| Per-sub-agent compaction policy | one session-wide override; nothing per agent type; `PreCompact` not documented inside sub-agents | needs a harness change: `agent_id` on `PreCompact` and a frontmatter threshold |

Binary-only facts: idle compaction is gated by a server flag, default off, fires at 90% of a
200K-token floor, `idleCompaction: false` disables it, `precomputeCompactionEnabled` exists. The
tweet that prompted this is answered in one setting and one hook.
